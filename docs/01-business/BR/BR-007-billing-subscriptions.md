| Параметр | Значение |
|----------|----------|
| **Статус** | ✅ APPROVE |
| **Дата утверждения** | 2026-04-29 |
| **Комментарий** | Основа монетизации тренерского кабинета |
| **Приоритет MVP** | Phase 2 |

## Business Value

Позволяет тренеру понимать ценность тарифов и обеспечивает предсказуемую рекуррентную выручку платформы.

## Определение активного клиента для тарификации

Для MVP продукт не применяет биллинговые лимиты. Каноническое определение из `GLOSSARY.md` сохраняется как резерв для Phase 2: активный клиент считается по связке «клиент–конкретный тренер» при наличии значимого действия за последние 30 календарных дней; простой вход в кабинет без значимого действия не считается активностью для тарификации.

## Приоритет реализации

- **MVP:** не входит в обязательный продуктовый scope; платёжная гипотеза проверяется вручную или через внешние процессы без продуктовой интеграции.
- **Phase 2:** отображение тарифа и лимитов, апгрейд, автоплатежи, статусы оплаты, dunning, self-service смена платёжного метода, годовые тарифы и промо-механики.


## User Stories

### US-R007-001: Прозрачные лимиты и апгрейд

* **As a** тренер
* **I want** видеть ограничения и ценность следующего тарифа
* **So that** апгрейд выглядел естественным

**Scope:** Phase 2.

**Acceptance Criteria:**

* **AC-R007-U001-001:**
    * **Given:** я использую базовый тариф
    * **When:** приближаюсь к лимиту активных клиентов
    * **Then:** система заранее уведомляет меня о лимите
* **AC-R007-U001-002:**
    * **Given:** мне нужна функция более высокого тарифа
    * **When:** я пытаюсь её использовать
    * **Then:** вижу value-based upgrade prompt

## Метрики успеха

- ≥ 5 пилотных тренеров подтверждают готовность платить после прохождения критического пути MVP;
