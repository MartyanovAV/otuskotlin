# BR-010: Trainer-first MVP с публичной ссылкой на тренировочный план

## Статус

| Параметр | Значение |
|----------|----------|
| **Статус** | ✅ Утверждён |
| **Дата утверждения** | 2026-05-27 |
| **Комментарий** | Канонический бизнес-scope trainer-first MVP с публичной ссылкой на тренировочный план |
| **Приоритет MVP** | P0 |

## Бизнес-ценность

MVP с публичной ссылкой на тренировочный план проверяет, готов ли независимый тренер получать и оплачивать ценность от минимального рабочего контура «клиентская карточка → тренировочный план → публичная ссылка → отметка выполнения» без регистрации клиента и без полноценной модели клиентского владения данными на первом шаге.

## Бизнес-гипотеза

Если тренер может за несколько минут создать клиентскую карточку, выдать план по публичной ссылке и увидеть факт выполнения, то FitBridge способен доказать trainer-first B2B-ценность раньше, чем будет построена полная client-owned модель с клиентскими аккаунтами, гранулярными правами и переносимостью истории.

## Целевой сценарий

1. Тренер регистрируется как единственный зарегистрированный пользователь MVP.
2. Тренер создаёт минимальную клиентскую карточку `ClientCard`.
3. Тренер создаёт простой тренировочный план `TrainingPlan`.
4. Система генерирует публичную ссылку на план.
5. Клиент без регистрации открывает ссылку, видит план и оставляет отметку выполнения `CompletionMark`.
6. Тренер видит статус выполнения в карточке клиента или списке клиентов.
7. Тренер может закрыть доступ по ссылке, после чего клиент больше не должен видеть план по этой ссылке.

## Персоны и участники

| Участник | Роль в MVP | Ключевая мотивация |
|---|---|---|
| Тренер | Единственный зарегистрированный пользователь и основной покупатель | Быстро проверить, что клиент получил план и выполнил тренировку, без хаоса в чатах |
| Клиент по ссылке | Незарегистрированный получатель плана | Открыть план без установки приложения и быстро отметить выполнение |
| Владелец продукта / пилот | Наблюдатель метрик пилота | Проверить willingness-to-pay trainer-first сценария до расширения модели |

## Входит в объём

- Регистрация и минимальный рабочий контур только для тренера.
- Создание минимальной клиентской карточки тренером.
- Создание простого тренировочного плана тренером.
- Генерация публичной ссылки на план для клиента.
- Просмотр плана клиентом без регистрации.
- Отметка выполнения клиентом без регистрации.
- Просмотр тренером статуса выполнения.
- Закрытие доступа по ссылке тренером.
- Канонические MVP-сущности: `ClientCard`, `TrainingPlan`, `CompletionMark`.

## Не входит в объём

- Регистрация клиента.
- Личный кабинет клиента.
- Полная client-owned модель как обязательство MVP.
- `AccessGrant` и полноценная модель прав доступа.
- Multi-specialist и командные сценарии.
- Биллинг и тарифные лимиты внутри продукта.
- Библиотека упражнений, шаблоны, AI-генерация программ.
- Расширенная аналитика, отчёты, графики, экспорт.
- Чат, уведомления как отдельный продуктовый контур.
- Медицинские данные, замеры, фото, видео и rich-media.
- Переносимость истории между тренерами.

## Приоритет реализации

- **MVP / P0:** один тренер, минимальные клиентские карточки, простые планы, публичная ссылка, отметка выполнения, статус для тренера, закрытие ссылки.
- **После подтверждения гипотезы:** клиентский аккаунт, client-owned профиль, AccessGrant, переносимость истории, granular permissions и multi-specialist расширение.

## Пользовательские истории

### US-R010-001: Создание минимальной клиентской карточки

* **As a** тренер
* **I want** создать минимальную карточку клиента
* **So that** назначить план без регистрации клиента и без долгого onboarding

**Критерии приёмки:**

* **AC-R010-U001-001:**
    * **Given:** тренер зарегистрирован в FitBridge
    * **When:** тренер создаёт клиентскую карточку с минимально необходимыми данными
    * **Then:** карточка доступна тренеру для назначения плана
* **AC-R010-U001-002:**
    * **Given:** клиентская карточка создана
    * **When:** тренер открывает список клиентов
    * **Then:** он видит карточку и текущий статус назначенного плана, если план уже создан

### US-R010-002: Создание плана и публичной ссылки

* **As a** тренер
* **I want** создать тренировочный план и отправить клиенту публичную ссылку
* **So that** клиент увидел задание без регистрации и установки приложения

**Критерии приёмки:**

* **AC-R010-U002-001:**
    * **Given:** у тренера есть клиентская карточка
    * **When:** тренер создаёт простой тренировочный план
    * **Then:** план связывается с выбранной клиентской карточкой
* **AC-R010-U002-002:**
    * **Given:** план создан
    * **When:** тренер запрашивает ссылку
    * **Then:** система предоставляет публичную ссылку для клиента

### US-R010-003: Просмотр плана и отметка выполнения клиентом

* **As a** клиент по ссылке
* **I want** открыть план без регистрации и отметить выполнение
* **So that** тренер увидел мой статус без дополнительных сообщений в чате

**Критерии приёмки:**

* **AC-R010-U003-001:**
    * **Given:** клиент получил активную публичную ссылку
    * **When:** он открывает ссылку
    * **Then:** он видит назначенный тренировочный план без регистрации
* **AC-R010-U003-002:**
    * **Given:** клиент видит план по активной ссылке
    * **When:** он отмечает выполнение
    * **Then:** создаётся отметка выполнения, доступная тренеру в статусе плана

### US-R010-004: Контроль статуса и закрытие ссылки тренером

* **As a** тренер
* **I want** видеть статус выполнения и закрывать ссылку
* **So that** управлять сопровождением клиента без полноценной модели прав в MVP

**Критерии приёмки:**

* **AC-R010-U004-001:**
    * **Given:** клиент оставил отметку выполнения
    * **When:** тренер открывает карточку клиента или список клиентов
    * **Then:** тренер видит актуальный статус выполнения
* **AC-R010-U004-002:**
    * **Given:** публичная ссылка активна
    * **When:** тренер закрывает доступ по ссылке
    * **Then:** клиент больше не может просматривать план и оставлять новые отметки по этой ссылке

## Бизнес-ограничения

| Ограничение | Значение | Комментарий |
|--------------|-----------|-------|
| Пользовательская модель MVP | Только тренер зарегистрирован | Клиент не создаёт аккаунт и не проходит onboarding |
| Модель данных MVP | `ClientCard`, `TrainingPlan`, `CompletionMark` | `AccessGrant` не входит в MVP |
| Scope discipline | Trainer-first B2B validation | MVP не проверяет полную client-owned модель |
| Клиентский доступ | Только по публичной ссылке | Тренер может закрыть доступ |

## Метрики успеха

- ≥ 55% пилотных тренеров создают первую связку «клиентская карточка + план + ссылка» в течение 7 дней.
- Median time-to-first-plan-link ≤ 1 день после регистрации тренера.
- ≥ 50% отправленных активных ссылок получают хотя бы одну отметку выполнения в течение 14 дней.
- ≥ 60% активированных тренеров возвращаются к просмотру статусов выполнения в течение 14 дней.
- ≥ 5 пилотных тренеров подтверждают готовность платить за trainer-first контур после прохождения сценария.
- ≤ 10% пилотных клиентов требуют регистрации или личного кабинета как блокер первого использования.

## Риски и компромиссы

| Риск / компромисс | Влияние | Продуктовая позиция MVP |
|---|---|---|
| Клиент не владеет историей на первом шаге | Может ослабить стратегическую дифференциацию | Явно фиксируем публичную ссылку на план как быстрый trainer-first эксперимент, а не финальную модель |
| Публичная ссылка проще полноценной модели прав | Требует осторожного ограничения данных в плане | В MVP не включать медданные, фото/видео и чувствительные данные |
| Нет клиентского кабинета | Меньше retention-механик клиента | Проверяем только факт выполнения и ценность для тренера |
| Нет переносимости истории между тренерами | Ограничивает client-owned promise | Переносимость возвращается после подтверждения B2B-ценности |
| Риск scope creep | Может сорвать быстрый пилот | Все клиентские аккаунты, AccessGrant, аналитика и биллинг остаются вне scope |

## Связь с будущей client-owned моделью

MVP публичного доступа к плану не отменяет стратегическое направление FitBridge на client-owned данные. Он является более узким validation wedge: сначала доказать, что тренер получает повторяемую ценность и готов платить за рабочий контур. После подтверждения метрик публичная ссылка, данные и сценарии могут стать входом в будущую модель, где клиент регистрируется, получает собственный профиль, управляет доступами, переносит историю между тренерами и подключает нескольких специалистов.

## Вне объёма

- Клиентская регистрация и клиентский личный кабинет.
- Полноценная выдача, подтверждение и отзыв прав доступа клиентом.
- Одновременная работа нескольких специалистов с одним клиентом.
- Командная CRM для студий.
- Встроенная монетизация, платежи и тарифные лимиты.
- Расширенная аналитика, отчётность, библиотека упражнений, чат, медиа и медданные.
