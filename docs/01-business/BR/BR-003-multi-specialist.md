# BR-003: Работа с несколькими специалистами

## Статус

| Параметр | Значение |
|----------|----------|
| **Статус** | ✅ APPROVE |
| **Дата утверждения** | 2026-04-29 |
| **Комментарий** | Основа будущего expansion в смежные вертикали |
| **Приоритет MVP** | Phase 2 |

## Business Value

Открывает сценарий совместной работы тренера, нутрициолога и реабилитолога внутри одного профиля клиента.

## Приоритет реализации

- **MVP:** не входит в обязательный первый коммерческий релиз; допускается только design reserve и ручной пилот со вторым специалистом.
- **Phase 2:** полноценные роли специалистов, параллельный доступ и разграничение видимости по задачам.


## User Stories

### US-R003-001: Подключение нескольких специалистов

* **As a** клиент
* **I want** подключать нескольких специалистов
* **So that** они могли работать в одном контуре

**Acceptance Criteria:**

* **AC-R003-U001-001:**
    * **Given:** у меня уже есть активный тренер
    * **When:** я подключаю второго специалиста
    * **Then:** система не блокирует параллельную работу
* **AC-R003-U001-002:**
    * **Given:** у специалистов разные роли
    * **When:** они открывают мой профиль
    * **Then:** каждый видит только релевантный набор данных и задач

## System Constraints

| Constraint   | Value     | Notes |
|--------------|-----------|-------|
| Latency      | < 1000 ms | Проверка ролевого доступа |
| Throughput   | 20 req/sec | Достаточно для MVP |
| Availability | 99.5%     | Важна консистентность прав |

## Метрики успеха

- ≥ 12% платящих аккаунтов используют 2+ специалистов к концу 24-го месяца;
- ≥ 80% пилотных multi-specialist аккаунтов подтверждают ценность сценария в интервью.


## Out of Scope

- Маркетплейс специалистов
- Автоматическое распределение клиентов между специалистами
