# BR-002: Контроль доступа к данным клиента

## Статус

| Параметр | Значение |
|----------|----------|
| **Статус** | ✅ APPROVE |
| **Дата утверждения** | 2026-04-29 |
| **Комментарий** | Ключевая дифференциация будущей client-owned модели; MVP использует закрытие публичной ссылки тренером |
| **Приоритет MVP** | Phase 2 / после проверки BR-010 trainer-first MVP с публичной ссылкой |

## Business Value

Даёт клиенту контроль над данными в будущей client-owned модели. В выбранном MVP публичного доступа к плану полноценный `AccessGrant`, клиентское подтверждение доступа и отзыв доступа клиентом не реализуются.

## Приоритет реализации

- **MVP с публичной ссылкой:** `AccessGrant` не входит в scope; клиент открывает план по публичной ссылке без регистрации, а тренер может закрыть доступ по ссылке. Канонический MVP описан в [BR-010](BR-010-public-plan-link-mvp.md).
- **Операции пилота MVP:** в MVP нет in-product ADMIN/support роли, личного кабинета администратора или support console. Допустимо операционное администрирование пилота через Keycloak и контролируемый operational runbook/provisioning: допуск или отзыв пилотных тренеров, блокировка пользователя, обработка invite/access edge cases и фиксация действия в audit/log без чувствительных данных. Это не является пользовательской ролью продукта и не даёт broad bypass к domain API.
- **Phase 2:** несколько специалистов, более тонкие права по типам данных и временные доступы; полноценный admin UI/support console и гранулярные операторские роли.


## User Stories

### US-R002-001: Выдача и отзыв доступа тренерам

* **As a** клиент
* **I want** выдавать и отзывать доступ тренеру
* **So that** только выбранные специалисты видели мой прогресс

**Acceptance Criteria:**

* **AC-R002-U001-001:**
    * **Given:** тренер отправил мне приглашение
    * **When:** я принимаю приглашение
    * **Then:** доступ к моим данным выдаётся тренеру только после моего явного подтверждения; это относится к Phase 2 client-owned модели, а не к MVP публичного доступа к плану
* **AC-R002-U001-002:**
    * **Given:** тренер уже подключён
    * **When:** я отзываю доступ
    * **Then:** тренер теряет право просмотра разрешённых полей профиля и право изменения тренировочного процесса клиента
* **AC-R002-U001-003:**
    * **Given:** у меня есть активный тренер
    * **When:** я открываю экран доступов
    * **Then:** вижу статус доступа и могу его отозвать

### US-R002-002: Смена тренера без потери истории

* **As a** клиент
* **I want** отключить тренера без потери данных
* **So that** мой прогресс оставался со мной

**Acceptance Criteria:**

* **AC-R002-U002-001:**
    * **Given:** у меня есть история занятий
    * **When:** я отключаю старого тренера
    * **Then:** история остаётся в профиле без удаления
* **AC-R002-U002-002:**
    * **Given:** я подключаю нового тренера после пилота
    * **When:** выдаю ему доступ
    * **Then:** он видит накопленный baseline после моего подтверждения

### US-R002-003: Операционное администрирование пилота без продуктовой ADMIN-роли

* **As a** владелец пилота FitBridge
* **I want** обрабатывать ограниченные операционные случаи доступа вне пользовательского продукта
* **So that** пилот можно безопасно сопровождать без раскрытия клиентских данных и без расширения MVP scope

**Acceptance Criteria:**

* **AC-R002-U003-001:**
    * **Given:** нужен допуск или отзыв пилотного тренера
    * **When:** операция выполняется через контролируемый operational runbook/provisioning
    * **Then:** действие не создаёт in-product ADMIN/support роль, не обходит owner/grant/scope policy и фиксируется в audit/log без чувствительных данных
* **AC-R002-U003-002:**
    * **Given:** нужен разбор invite/access edge case или блокировка пользователя
    * **When:** support/ops выполняет разрешённое операционное действие пилота
    * **Then:** оператор не получает права читать профиль клиента, дневник, тренировочную историю или health-adjacent данные
* **AC-R002-U003-003:**
    * **Given:** обычный domain API вызывается пользователем продукта
    * **When:** проверяется доступ к данным клиента
    * **Then:** допустимы только роли CLIENT/TRAINER с active owner/grant/scope; broad bypass для support/admin отсутствует

## System Constraints

| Constraint   | Value     | Notes |
|--------------|-----------|-------|
| Latency      | < 1000 ms | Операции с доступами |
| Throughput   | 20 req/sec | Пиковые операции редки |
| Availability | 99.9%     | Критично для доверия и комплаенса |

## Метрики успеха

- ≥ 90% операций выдачи/отзыва доступа завершаются без обращения в поддержку;
- доля клиентов, сохранивших историю при смене тренера, = 100%.


## Out of Scope

- Публичный обмен данными между пользователями
- Неограниченное делегирование прав третьим лицам
- Одновременная работа нескольких специалистов с одним клиентом
- Гранулярные scopes по типам данных
- Редактирование профиля клиента тренером / trainer `PROFILE_WRITE` для клиентского профиля в MVP
- `AccessGrant`, клиентское подтверждение доступа и отзыв доступа клиентом в MVP публичного доступа к плану
- In-product ADMIN/support UI, личный кабинет администратора, support console и гранулярные operator roles в MVP
- Любой broad bypass для support/admin к профилю клиента, дневнику, тренировочной истории и health-adjacent данным
