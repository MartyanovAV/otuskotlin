# BR-009: Согласия, приватность и удаление профиля

## Статус

| Параметр | Значение |
|----------|----------|
| **Статус** | ✅ APPROVE |
| **Дата утверждения** | 2026-05-27 |
| **Комментарий** | Минимальные privacy-границы MVP с публичной ссылкой; расширенная privacy/deletion модель переносится после MVP |
| **Приоритет MVP** | P0 только для границ публичной ссылки и запрета чувствительных данных; остальное Phase 2 |

## Business Value

Снижает юридические и репутационные риски FitBridge в trainer-first MVP с публичной ссылкой за счёт узкого набора данных, отсутствия медданных/медиа и понятного закрытия публичной ссылки тренером. Полноценный пользовательский контроль над данными относится к будущей client-owned модели.

## Приоритет реализации

- **MVP с публичной ссылкой / P0:** минимальная обработка данных тренера и клиентской карточки, отображение по публичной ссылке только информации, необходимой для выполнения плана, запрет медданных, фото/видео, health-adjacent расширений и чувствительных payload в логах. Тренер может закрыть публичную ссылку.
- **Профильные поля MVP:** клиентский профиль, `gender`, `goals`, `heightCm`, замеры и другие расширенные профильные данные не входят в MVP публичного доступа к плану.
- **Операции пилота MVP:** допустимы только контролируемые действия без in-product ADMIN/support UI и без чтения чувствительных клиентских данных.
- **Phase 2:** клиентская регистрация, согласия клиента, отзыв согласия, запрос удаления/архивации профиля, granular consent, полноценный audit/event trail, data retention policy, self-service экспорт данных, полноценный support console/admin UI и расширенные процессы для командных аккаунтов.

## User Stories

### US-R009-001: Минимальное информирование и границы публичной ссылки

* **As a** тренер и клиент по ссылке
* **I want** понимать, что в MVP с публичной ссылкой обрабатывается минимальный набор данных
* **So that** использовать ссылку без раскрытия лишней информации

**Acceptance Criteria:**

* **AC-R009-U001-001:**
    * **Given:** тренер регистрируется
    * **When:** он начинает использовать MVP-сценарий публичной ссылки
    * **Then:** он принимает необходимые условия обработки данных для работы с клиентскими карточками и планами
* **AC-R009-U001-002:**
    * **Given:** клиент открывает публичную ссылку
    * **When:** он просматривает план
    * **Then:** на странице не запрашиваются медданные, фото/видео, замеры или расширенные профильные поля
* **AC-R009-U001-003:**
    * **Given:** тренер закрывает публичную ссылку
    * **When:** клиент повторно открывает ссылку
    * **Then:** план и отметка выполнения по этой ссылке больше недоступны
* **AC-R009-U001-004:**
    * **Given:** клиент использует публичную ссылку
    * **When:** он отмечает выполнение
    * **Then:** отметка не требует регистрации клиента или создания клиентского профиля

### US-R009-002: Отзыв согласия и запрос удаления/архивации профиля

**Приоритет:** Phase 2 / за пределами MVP публичного доступа к плану.

* **As a** пользователь
* **I want** отозвать согласие и запросить удаление или архивацию профиля
* **So that** контролировать дальнейшую обработку моих данных

**Acceptance Criteria:**

* **AC-R009-U002-001:**
    * **Given:** у меня есть активный профиль
    * **When:** я отзываю согласие на обработку данных
    * **Then:** система фиксирует статус отзыва и прекращает новые пользовательские операции обработки, кроме необходимых действий завершения/архивации
* **AC-R009-U002-002:**
    * **Given:** я отправил запрос удаления или архивации профиля
    * **When:** запрос принят системой
    * **Then:** я вижу понятный статус запроса, а профиль переводится в состояние, недоступное тренерам
* **AC-R009-U002-003:**
    * **Given:** мой профиль архивирован или помечен к удалению
    * **When:** ранее подключённый тренер открывает список клиентов или карточку клиента
    * **Then:** мои данные не отображаются как доступные для просмотра, а тренировочный процесс недоступен тренеру для изменений

### US-R009-003: Ограничение логирования чувствительных данных

**Приоритет:** P0 для MVP публичного доступа к плану.

* **As a** пользователь
* **I want** чтобы мои чувствительные данные не попадали в технические логи
* **So that** снизить риск раскрытия персональной информации при поддержке и расследовании инцидентов

**Acceptance Criteria:**

* **AC-R009-U003-001:**
    * **Given:** тренер создаёт клиентскую карточку или план, либо клиент оставляет отметку выполнения
    * **When:** система логирует событие
    * **Then:** в лог попадают только технические идентификаторы, тип действия, время и итоговый статус без текста комментариев, health-adjacent значений и содержимого плана
* **AC-R009-U003-002:**
    * **Given:** произошёл отзыв согласия, удаление или архивация профиля
    * **When:** система фиксирует событие для поддержки и аудита
    * **Then:** запись не раскрывает чувствительные поля и не восстанавливает содержимое пользовательских данных

### US-R009-004: Privacy/deletion support actions без доступа к чувствительным данным

**Приоритет:** Phase 2 / за пределами MVP публичного доступа к плану, кроме контролируемых пилотных операций без чтения данных.

* **As a** пользователь пилота
* **I want** чтобы операционная помощь по приватности и удалению не раскрывала мои данные поддержке
* **So that** доверие к модели client-owned data сохранялось даже при ручном сопровождении MVP

**Acceptance Criteria:**

* **AC-R009-U004-001:**
    * **Given:** пользователь запросил удаление, архивирование или помощь с отзывом согласия
    * **When:** support/ops выполняет разрешённое privacy/deletion support action по runbook
    * **Then:** действие ограничено статусом/процессом запроса и не предоставляет чтение профиля клиента, дневника, тренировочной истории или health-adjacent data
* **AC-R009-U004-002:**
    * **Given:** privacy/deletion support action выполнено
    * **When:** действие фиксируется для контроля
    * **Then:** audit/log содержит только технические идентификаторы, тип действия, время и результат без чувствительных данных
* **AC-R009-U004-003:**
    * **Given:** требуется полноценная support console, admin UI или гранулярные operator roles
    * **When:** оценивается MVP scope
    * **Then:** эти возможности считаются Phase 2/out of MVP

## System Constraints

| Constraint | Value | Notes |
|--------------|-----------|-------|
| Latency | < 1000 ms | Закрытие публичной ссылки и базовые privacy-действия пилота |
| Throughput | 20 req/sec | Операции редкие, но должны быть предсказуемыми |
| Availability | 99.9% | Закрытие публичной ссылки и запрет чувствительных данных критичны для доверия |
| Logging | No sensitive payloads | В логах запрещены тексты комментариев, health-adjacent значения и содержимое планов/отметок |

## Метрики успеха

- 100% публичных ссылок не запрашивают регистрацию клиента, медданные, фото/видео, замеры и расширенные профильные поля;
- 100% закрытых тренером ссылок перестают показывать план и принимать новые отметки выполнения;
- 0 подтверждённых случаев попадания чувствительных пользовательских payload в продуктовые или инфраструктурные логи MVP.

## Out of Scope

- Полная юридическая экспертиза пользовательских документов внутри BR
- Granular consent по каждому типу данных и каждому специалисту
- Self-service экспорт всех данных пользователя
- Продуктовый `AuditEvent` и расширенный юридический audit trail
- Автоматизированные уведомления через отдельный `Notification`-контур
- Медицинские заключения, диагностика и обработка данных как медицинским изделием
- In-product ADMIN/support UI, support console и гранулярные operator roles для privacy/deletion операций в MVP
- Чтение support/admin пользовательского профиля клиента, дневника, тренировочной истории или health-adjacent данных
