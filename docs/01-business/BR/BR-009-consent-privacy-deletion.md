# BR-009: Согласия, приватность и удаление профиля

## Статус

| Параметр | Значение |
|----------|----------|
| **Статус** | ✅ APPROVE |
| **Дата утверждения** | 2026-05-27 |
| **Комментарий** | Минимальные privacy-границы trainer-only MVP; расширенная consent/deletion модель переносится после MVP |
| **Приоритет MVP** | P0 для минимизации данных, ownership и запрета чувствительных payload в логах; остальное Phase 2 |

## Business Value

Снижает юридические и репутационные риски FitBridge за счёт узкого набора данных, приватного контура тренера и отсутствия медданных, медиа и клиентского доступа. Полноценный пользовательский контроль над данными относится к будущей client-owned модели.

## Приоритет реализации

- **Текущий MVP / P0:** минимальная обработка данных тренера, `ClientCard` и `TrainingPlan`; доступ только тренеру-владельцу; запрет медданных, фото/видео, health-adjacent расширений и чувствительных payload в логах.
- **Профильные поля MVP:** клиентский профиль, `gender`, `goals`, `heightCm`, замеры и другие расширенные профильные данные не входят в MVP.
- **Операции пилота MVP:** допустимы только контролируемые действия без in-product ADMIN/support UI и без чтения клиентских данных.
- **Phase 2:** клиентская регистрация и доступ к плану, публичные ссылки, согласия клиента, отзыв согласия, запрос удаления/архивации профиля, granular consent, полноценный audit trail, data retention policy, self-service экспорт и support console/admin UI.

## User Stories

### US-R009-001: Минимальная обработка данных в приватном контуре тренера

* **As a** тренер
* **I want** использовать только минимальный набор данных о клиенте
* **So that** вести карточки и планы без неоправданного сбора чувствительной информации

**Acceptance Criteria:**

* **AC-R009-U001-001:**
    * **Given:** тренер регистрируется
    * **When:** он начинает использовать MVP
    * **Then:** он принимает необходимые условия обработки данных для работы с клиентскими карточками и планами
* **AC-R009-U001-002:**
    * **Given:** тренер создаёт клиентскую карточку или план
    * **When:** система принимает и сохраняет данные
    * **Then:** MVP не запрашивает медданные, фото/видео, замеры и расширенные профильные поля
* **AC-R009-U001-003:**
    * **Given:** создана клиентская карточка или план
    * **When:** другой тренер пытается прочитать или изменить объект
    * **Then:** операция отклоняется проверкой ownership

### US-R009-002: Отзыв согласия и запрос удаления/архивации профиля

**Приоритет:** Phase 2 / за пределами текущего MVP.

* **As a** пользователь
* **I want** отозвать согласие и запросить удаление или архивацию профиля
* **So that** контролировать дальнейшую обработку моих данных

**Acceptance Criteria:**

* **AC-R009-U002-001:** после отзыва согласия система прекращает новые пользовательские операции обработки, кроме необходимых действий завершения или архивации.
* **AC-R009-U002-002:** пользователь видит понятный статус принятого запроса удаления или архивации.
* **AC-R009-U002-003:** архивированный или помеченный к удалению профиль и связанный тренировочный процесс недоступны ранее подключённым специалистам.

### US-R009-003: Ограничение логирования чувствительных данных

**Приоритет:** P0 для текущего MVP.

* **As a** пользователь
* **I want** чтобы мои данные не попадали в технические логи
* **So that** снизить риск раскрытия информации при поддержке и расследовании инцидентов

**Acceptance Criteria:**

* **AC-R009-U003-001:**
    * **Given:** тренер выполняет операцию с клиентской карточкой или планом
    * **When:** система логирует событие
    * **Then:** в лог попадают только технические идентификаторы, тип действия, время и итоговый статус без персональных полей и содержимого плана
* **AC-R009-U003-002:**
    * **Given:** выполняется операционное действие пилота
    * **When:** оно фиксируется для поддержки или аудита
    * **Then:** запись не раскрывает пользовательские данные и не позволяет восстановить содержимое объектов

### US-R009-004: Privacy/deletion support actions без доступа к данным

**Приоритет:** Phase 2, кроме контролируемых пилотных операций без чтения данных.

* **As a** пользователь пилота
* **I want** чтобы операционная помощь по приватности и удалению не раскрывала мои данные поддержке
* **So that** ручное сопровождение не создавало обход доменной авторизации

**Acceptance Criteria:**

* **AC-R009-U004-001:** support/ops action ограничивается статусом и процессом запроса и не предоставляет чтение профиля, карточек или планов.
* **AC-R009-U004-002:** audit/log содержит только технические идентификаторы, тип действия, время и результат.
* **AC-R009-U004-003:** полноценная support console, admin UI и гранулярные operator roles считаются Phase 2.

## System Constraints

| Constraint | Value | Notes |
|------------|-------|-------|
| Latency | < 1000 ms | Проверка JWT и ownership не должна нарушать целевой отклик MVP-операций |
| Throughput | 20 req/sec | Нагрузка пилота невелика, но обработка должна быть предсказуемой |
| Availability | 99.9% | Приватность и запрет неавторизованного доступа критичны для доверия |
| Logging | No user payloads | В логах запрещены персональные поля и содержимое клиентских карточек и планов |

## Метрики успеха

- 100% MVP-операций с `ClientCard` и `TrainingPlan` требуют аутентификацию тренера и проверку ownership.
- 100% MVP-моделей ограничены утверждённым набором полей и не включают медданные, фото/видео и замеры.
- 0 подтверждённых случаев попадания пользовательских payload в продуктовые или инфраструктурные логи MVP.

## Out of Scope

- Клиентская регистрация, клиентский кабинет и клиентский доступ к плану
- Публичные ссылки и capability-token
- Отметки о выполнении тренировок клиентом
- Полная юридическая экспертиза пользовательских документов внутри BR
- Granular consent по каждому типу данных и каждому специалисту
- Self-service экспорт, переносимость и гарантированное физическое удаление из backup
- In-product ADMIN/support UI, support console и гранулярные operator roles
