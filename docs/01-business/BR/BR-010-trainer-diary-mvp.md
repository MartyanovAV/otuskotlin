# BR-010: Trainer-first MVP "Дневник тренера"

## Статус

| Параметр             | Значение                                                      |
|----------------------|---------------------------------------------------------------|
| **Статус**           | ✅ Утверждён                                                   |
| **Дата утверждения** | 2026-05-27                                                    |
| **Комментарий**      | Канонический бизнес-scope trainer-first MVP "Дневник тренера" |
| **Приоритет MVP**    | P0                                                            |

## Business Value

MVP "Дневник тренера" проверяет, готов ли независимый тренер получать ценность от минимального рабочего контура «клиентская база → тренировочные планы» без регистрации клиента и без полноценной модели клиентского владения данными на первом шаге.

## Приоритет реализации

- **MVP / P0:** один тренер, минимальные клиентские карточки (создание, поиск), простые планы (создание, поиск).
- **После подтверждения гипотезы:** клиентский аккаунт, client-owned профиль, AccessGrant, переносимость истории, granular permissions и multi-specialist расширение.

## User Stories

### US-R010-001: Создание минимальной клиентской карточки

* **As a** тренер
* **I want** создать минимальную карточку клиента
* **So that** вести базу клиентов без их регистрации и без долгого onboarding

**Acceptance Criteria:**

* **AC-R010-U001-001:**
    * **Given:** тренер зарегистрирован в FitBridge
    * **When:** тренер создаёт клиентскую карточку с минимально необходимыми данными
    * **Then:** карточка сохраняется в базе клиентов тренера
* **AC-R010-U001-002:**
    * **Given:** клиентская карточка создана
    * **When:** тренер открывает список клиентов
    * **Then:** он видит карточку в списке

### US-R010-002: Поиск и просмотр клиентов

* **As a** тренер
* **I want** искать и просматривать своих клиентов
* **So that** быстро находить нужного клиента в базе

**Acceptance Criteria:**

* **AC-R010-U002-001:**
    * **Given:** у тренера есть несколько клиентов
    * **When:** тренер вводит имя клиента в поиск
    * **Then:** система отображает подходящие карточки клиентов

### US-R010-003: Создание тренировочного плана

* **As a** тренер
* **I want** создать тренировочный план
* **So that** зафиксировать программу тренировок для клиента

**Acceptance Criteria:**

* **AC-R010-U003-001:**
    * **Given:** у тренера есть клиентская карточка
    * **When:** тренер создаёт простой тренировочный план
    * **Then:** план сохраняется в системе
* **AC-R010-U003-002:**
    * **Given:** план создан
    * **When:** тренер открывает список планов
    * **Then:** он видит созданный план

### US-R010-004: Поиск и просмотр планов

* **As a** тренер
* **I want** искать и просматривать тренировочные планы
* **So that** быстро находить нужный план

**Acceptance Criteria:**

* **AC-R010-U004-001:**
    * **Given:** у тренера есть несколько планов
    * **When:** тренер использует поиск по планам
    * **Then:** система отображает подходящие планы

## System Constraints

| Constraint                  | Value                         | Notes                                              |
|-----------------------------|-------------------------------|----------------------------------------------------|
| Пользовательская модель MVP | Только тренер зарегистрирован | Клиент не создаёт аккаунт и не проходит onboarding |
| Модель данных MVP           | `ClientCard`, `TrainingPlan`  | `AccessGrant` не входит в MVP                      |
| Scope discipline            | Trainer-first B2B validation  | MVP не проверяет полную client-owned модель        |

## Метрики успеха

- ≥ 55% пилотных тренеров создают первую связку «клиентская карточка + план» в течение 7 дней.
- Median time-to-first-plan ≤ 1 день после регистрации тренера.
- ≥ 60% активированных тренеров возвращаются к просмотру списка клиентов и планов в течение 14 дней.
- ≥ 5 пилотных тренеров подтверждают готовность платить за trainer-first контур после прохождения сценария.
