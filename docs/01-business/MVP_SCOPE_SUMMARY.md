# MVP Scope Summary

| Параметр | Значение |

| **Статус** | ✅ APPROVE |

| **Комментарий** | Сводный one-page scope сокращённого MVP FitBridge |

## Business Value

Фиксирует минимальный проверяемый объём FitBridge для Gate 1. Проверяются два пути: 
1. **Trainer-led:** один тренер подключает клиента, читает разрешённые поля профиля, назначает простой план, клиент или тренер отмечает выполнение в рамках тренировочного процесса, обе стороны видят базовую историю.
2. **Solo-client (PLG):** клиент сам создаёт себе программу и заполняет дневник, чтобы позже стать драйвером привлечения тренера.
Всё, что не нужно для проверки этого цикла, переносится за пределы MVP.

## MVP Scope

| BR | Что входит в MVP |
|---|---|
| BR-001 | Профиль клиента, необязательные профильные поля `gender` и `goals` для контекста планирования без блокировки onboarding, ручное внесение тренировок, базовые комментарии к тренировке (solo-client) |
| BR-002 | Приглашение и подтверждение доступа одного активного тренера, чтение разрешённых полей профиля без права редактировать профиль клиента, отзыв доступа, сохранение истории клиента; операционное администрирование пилота только вне продукта через Keycloak/runbook без ADMIN/support роли и без broad bypass |
| BR-004 | Создание простого индивидуального плана без шаблонов (тренером или клиентом самостоятельно), назначение, редактирование тренировочного процесса и отметка выполнения |
| BR-005 | Базовая история тренировок и статус выполнения в карточке клиента без отдельного отчётного модуля |
| BR-006 | Регистрация тренера, подключение первого клиента по ссылке/коду, минимальный список клиентов |
| BR-007 | Не входит в MVP; допускается ручная валидация платёжной гипотезы вне продукта |
| BR-009 | Согласие на обработку ПДн, отдельное информирование о health-adjacent данных, отзыв согласия, запрос удаления/архивации профиля и блокировка доступов тренеров; privacy/deletion support actions только как controlled operations без чтения чувствительных данных |

### Design reserve / pilot only
- **BR-003:** multi-specialist сценарий не входит в обязательный первый коммерческий релиз; допустим только ручной пилот и design reserve.
- **BR-008:** командный сценарий студии не входит в обязательный первый коммерческий релиз; допустимы только design-partner пилоты.
- **ADMIN/support для MVP:** полноценного in-product ADMIN/support UI, ЛК администратора и support console нет. Допустимы только controlled operational runbook/provisioning для пилота: допуск/отзыв пилотных тренеров, блокировка пользователя, обработка invite/access edge cases и privacy/deletion support actions. Это не пользовательская роль продукта; domain API остаётся CLIENT/TRAINER only, а owner/grant/scope policy применяется всегда.
- **BR-005 расширение:** графики замеров, adherence-отчёты, экспорт и premium-аналитика переносятся после MVP.
- **Профильные body metrics:** `heightCm` не входит в MVP required/supported profile fields и переносится в Phase 2 / later measurement scope вместе с замерами и показателями тела.
- **BR-007:** тарифы, лимиты, апгрейд, автоплатежи и dunning переносятся после MVP.
- **BR-009 расширение:** granular consent, продуктовый `AuditEvent`, self-service экспорт данных и расширенная юридическая/аудит-модель переносятся в Phase 2.

### Критический сквозной путь MVP

**Путь А: Тренер-ориентированный (Trainer-led)**
1. Тренер регистрируется.
2. Приглашает первого клиента.
3. Клиент принимает доступ и получает свой профиль/дневник.
4. Тренер создаёт и назначает простой план.
5. Клиент или тренер отмечает выполнение в рамках ведения тренировочного процесса; профиль клиента при этом не редактируется тренером.
6. Тренер видит статус выполнения и историю клиента в карточке.

**Путь Б: Клиент-ориентированный (PLG Solo-client)**
1. Клиент регистрируется самостоятельно.
2. Клиент сам создаёт себе программу тренировок.
3. Клиент сам назначает программу себе и отмечает выполнение.
4. Позже клиент может пригласить тренера.

## System Constraints

| Constraint | Value | Notes |
|-----------|-------|-------|
| Scope discipline | MVP pilot only | В MVP входят два критических пути: Trainer-led и Solo-client (PLG) |
| Commercial readiness | Deferred | Биллинг и тарифные ограничения не блокируют Gate 1 |
| Approval state | Approved | Документ утверждён; пересмотр при изменении scope MVP |

## Out of Scope

- Полноценный multi-specialist production-сценарий
- Командный тариф и shared client operations для студий
- AI-генерация программ и продвинутая аналитика
- Шаблоны программ и библиотека упражнений
- Отдельный модуль отчётов, экспорт отчётов и графики замеров
- Тарифы, лимиты, апгрейд, автоплатежи и платёжные напоминания
- Upload/storage фото, видео и любых rich-media материалов; возможен только design reserve/Phase 2
- Привычки, регулярные check-in и rich-media история
- Полноценный club ERP, маркетплейс специалистов и медицинская диагностика
- Отдельный `Notification` API/provider для push/email/lifecycle communications и продуктовый `AuditEvent` API/отдельная audit entity — перенесены в Phase 2; в MVP используется pull-model UI и infrastructure audit-oriented logging через ADR-006.
- Редактирование профиля клиента тренером / trainer `PROFILE_WRITE` для клиентского профиля.
- Требование обязательного заполнения `gender` или `goals` при onboarding без отдельного явного решения о required-статусе.
- `heightCm` как MVP required/supported profile field; рост относится к Phase 2 / later measurement and body metrics scope.
- In-product ADMIN/support роль, личный кабинет администратора, support console, granular operator roles и broad bypass к client profile/diary/training history/health-adjacent data.
