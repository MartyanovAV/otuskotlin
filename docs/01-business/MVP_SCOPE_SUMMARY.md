# MVP Scope Summary

## Статус

| Параметр | Значение |
|----------|----------|
| **Статус** | ✅ APPROVE |
| **Дата утверждения** | 2026-05-27 |
| **Комментарий** | Сводный one-page scope выбранного trainer-first MVP: "Дневник тренера" |

## Business Value

Фиксирует минимальный проверяемый объём FitBridge для Gate 1 после выбора trainer-first MVP: "Дневник тренера". MVP проверяет B2B-ценность для тренера: тренер как единственный зарегистрированный пользователь создаёт клиентскую карточку, ищет клиентов, создаёт тренировочный план, завершает его и ищет/просматривает планы.

MVP **не проверяет** публичные ссылки, самостоятельные клиентские отметки о выполнении, глубокую аналитику, полную client-owned модель, регистрацию клиента, личный кабинет клиента, `AccessGrant`, multi-specialist и переносимость истории между тренерами. Эти элементы остаются стратегическим направлением после подтверждения trainer-first ценности.

## MVP Scope

| BR | Что входит в MVP "Дневник тренера" |
|---|---|
| BR-010 | Канонический scope MVP "Дневник тренера": `ClientCard`, `TrainingPlan` (создание и завершение тренером), управление базой клиентов и планами, обзорный экран со счётчиками |
| BR-004 | Только часть про создание и завершение простого тренировочного плана тренером и поиск/список планов; solo-client создание плана не входит в MVP |
| BR-006 | Регистрация тренера, создание первого клиента как карточки, создание первого плана |
| BR-007 | Не входит в MVP; допускается ручная проверка willingness-to-pay вне продукта |
| BR-009 | Только минимальные privacy-границы; расширенная consent/deletion модель переносится после MVP |

### Design reserve / pilot only
- **BR-001:** полноценный клиентский дневник, клиентский профиль, самостоятельная регистрация клиента и client-owned история не входят в MVP; остаются Phase 2 / future client-owned scope.
- **BR-002:** `AccessGrant`, явное подтверждение доступа клиентом, отзыв доступа клиентом и granular permissions не входят в MVP.
- **BR-003:** multi-specialist сценарий не входит в MVP; допустим только как стратегический резерв.
- **BR-005:** глубокая сквозная аналитика, продвинутые отчёты и клиентские отметки о выполнении не входят в MVP (в MVP входит только базовый обзорный экран тренера).
- **BR-008:** командный сценарий студии не входит в MVP; допустимы только design-partner интервью без продуктовой реализации.
- **ADMIN/support для MVP:** полноценного in-product ADMIN/support UI, ЛК администратора и support console нет. Допустимы только controlled operational actions для пилота без чтения чувствительных клиентских данных.
- **Профильные body metrics:** `heightCm` не входит в MVP required/supported profile fields и переносится в Phase 2 / later measurement scope вместе с замерами и показателями тела.
- **BR-007:** тарифы, лимиты, апгрейд, автоплатежи и dunning переносятся после MVP.
- **BR-009 расширение:** granular consent, продуктовый `AuditEvent`, self-service экспорт данных и расширенная юридическая/аудит-модель переносятся в Phase 2.

### Критический сквозной путь MVP

**Путь: trainer-first сценарий "Дневник тренера"**
1. Тренер регистрируется.
2. Создаёт минимальную карточку клиента (список клиентов).
3. Создаёт и завершает простой тренировочный план (поиск/список планов).

### Аналитическая воронка MVP

| Этап | Проверяемый сигнал | Что не интерпретировать как MVP-scope |
|---|---|---|
| trainer signup | Тренер готов стартовать без долгого внедрения | Регистрация клиента |
| client card | Тренер создаёт минимальную карточку клиента | Client-owned профиль |
| plan | Тренер создаёт и завершает простой план | Библиотека упражнений и шаблоны |
| trainer review | Тренер возвращается к списку клиентов и планов | Продвинутая сквозная аналитика и биллинг |

Метрики воронки используются для решения о Phase 2 client-owned модели, но сами по себе не добавляют в MVP регистрацию клиента, переносимую историю или granular permissions.

## System Constraints

| Constraint | Value | Notes |
|-----------|-------|-------|
| Scope discipline | Только MVP "Дневник тренера" | В MVP входит один критический путь: trainer-first управление клиентами и планами |
| Commercial readiness | Deferred | Биллинг и тарифные ограничения не блокируют Gate 1 |
| Approval state | Approved | Документ утверждён; пересмотр при изменении scope MVP |

## Out of Scope

- Публичные ссылки на планы
- Самостоятельные клиентские отметки о выполнении (клиентский дневник)
- Продвинутая сквозная аналитика, отчёты и графики замеров (в MVP входит базовый обзорный дашборд тренера с агрегированными счётчиками)
- Регистрация клиента и личный кабинет клиента
- `AccessGrant`, полноценная модель прав, клиентское подтверждение/отзыв доступа
- Полноценный multi-specialist production-сценарий
- Командный тариф и shared client operations для студий
- AI-генерация программ и рекомендательные системы
- Шаблоны программ и библиотека упражнений
- Отдельный модуль отчётов и экспорт данных
- Тарифы, лимиты, апгрейд, автоплатежи и платёжные напоминания
- Upload/storage фото, видео и любых rich-media материалов; возможен только design reserve/Phase 2
- Привычки, регулярные check-in и rich-media история
- Полноценный club ERP, маркетплейс специалистов и медицинская диагностика
- Отдельный `Notification` API/provider для push/email/lifecycle communications и продуктовый `AuditEvent` API/отдельная audit entity — перенесены в Phase 2; в MVP используется pull-model UI и infrastructure audit-oriented logging через ADR-006.
- Требование обязательного заполнения `gender` или `goals` при onboarding без отдельного явного решения о required-статусе.
- `heightCm` как MVP required/supported profile field; рост относится к Phase 2 / later measurement and body metrics scope.
- In-product ADMIN/support роль, личный кабинет администратора, support console, granular operator roles и broad bypass к client profile/diary/training history/health-adjacent data.
- Solo-client PLG путь, самостоятельное создание программы клиентом и переносимость истории между тренерами.
