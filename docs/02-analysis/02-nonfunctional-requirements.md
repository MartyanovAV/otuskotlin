# Нефункциональные требования FitBridge

Документ фиксирует NFR текущего trainer-only MVP «Дневник тренера». Канонический бизнес-источник: [BR-010-trainer-diary-mvp.md](../01-business/BR/BR-010-trainer-diary-mvp.md).

## 1. Производительность

### 1.1. Регистрация и старт тренера

- **Параметры:** типовой запрос регистрации/перехода к стартовому сценарию — до 1000 мс.
- **Приоритет:** Высокий / MVP.

### 1.2. Операции с ClientCard

- **Параметры:** типовые create/read/update/archive/search операции — до 1000 мс без учёта внешней IAM-задержки.
- **Приоритет:** Высокий / MVP.

### 1.3. Операции с TrainingPlan

- **Параметры:** типовые create/read/update/archive/search операции — до 1200 мс для плана MVP-размера.
- **Приоритет:** Высокий / MVP.

## 2. Надёжность и целостность

### 2.1. Доступность приватного рабочего контура

- **Параметры:** целевая доступность основных функций пилота — не ниже 99,5% в расчётном месяце.
- **Приоритет:** Высокий / MVP.

### 2.2. Целостность связей

- **Параметры:** `TrainingPlan` всегда связан с существующей `ClientCard` того же тренера; операции другого владельца отклоняются; optimistic lock предотвращает незаметную потерю обновлений.
- **Приоритет:** Высокий / MVP.

### 2.3. Валидные состояния плана

- **Параметры:** доменная модель использует единый статус `ACTIVE` или `ARCHIVED`; несовместимые комбинации boolean-флагов невозможны.
- **Приоритет:** Высокий / MVP.

## 3. Безопасность и приватность

### 3.1. Аутентификация

- **Параметры:** 100% domain API операций требуют валидный JWT; исключения ограничены техническими health/metrics endpoints согласно security-конфигурации.
- **Приоритет:** Высокий / MVP.

### 3.2. Доменная авторизация

- **Параметры:** каждая read/write операция проверяет trainer capability и ownership; переданный `clientCardId` или `trainingPlanId` не считается правом доступа.
- **Приоритет:** Высокий / MVP.

### 3.3. Минимизация и логирование данных

- **Параметры:** MVP не принимает медданные, фото/видео и body metrics; structured logs не содержат персональные поля и содержимое планов/карточек.
- **Приоритет:** Высокий / MVP.

## 4. UX и совместимость

### 4.1. Рабочий путь тренера

- **Параметры:** основные операции «создать карточку → создать план → найти карточку/план» должны быть выполнимы без клиентского аккаунта и без промежуточной настройки прав.
- **Приоритет:** Высокий / MVP.

### 4.2. Совместимость API

- **Параметры:** v1/v2 сохраняют POST Full API discriminators и согласованные модели; breaking changes выполняются через новую версию контракта.
- **Приоритет:** Высокий / MVP.

## 5. Сопровождаемость и проверяемость

### 5.1. Трассировка требований

- **Параметры:** каждое MVP-требование трассируется к BR и acceptance-проверке. Публичный или клиентский доступ не добавляется без отдельного изменения scope.
- **Приоритет:** Средний / MVP governance.

### 5.2. Автоматическая проверка backend

- **Параметры:** изменения OpenAPI, generated transport, mappers, business logic и Ktor routes проверяются соответствующими unit/integration тестами и полным Gradle `check` training-service.
- **Приоритет:** Высокий / MVP.

### 5.3. Наблюдаемость

- **Параметры:** логи и метрики позволяют связать запрос с операцией и результатом без пользовательского payload; секреты и JWT не логируются.
- **Приоритет:** Высокий / MVP.

## 6. Аналитика пилота

### 6.1. Минимальные события воронки

- **Параметры:** измеряются регистрация тренера, создание первой `ClientCard`, создание первого `TrainingPlan` и возврат к поиску/просмотру объектов.
- **Приоритет:** Средний / MVP validation.

### 6.2. Интерпретация метрик

- **Параметры:** количественные метрики сопоставляются с интервью пилотных тренеров; отсутствие клиентского доступа учитывается как сознательное ограничение MVP.
- **Приоритет:** Средний / MVP validation.

## 7. Out of Scope / Phase 2 NFR

NFR для публичных ссылок/capability-token, клиентского кабинета, отметок выполнения, `AccessGrant`, multi-specialist, биллинга, расширенной аналитики, медиа и медданных уточняются отдельно перед соответствующей фазой и не являются условиями текущего MVP.
