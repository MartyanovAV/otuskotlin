# ADR-001: Использовать Keycloak как Identity Server

**Статус:** Accepted
**Дата:** 2026-05-19

## Контекст

FitBridge обрабатывает персональные и чувствительные фитнес-данные пользователей, включая профили тренеров, клиентские карточки, планы тренировок и отчёты/отметки выполнения. Для trainer-first MVP с публичной ссылкой системе необходима надёжная регистрация и аутентификация тренера как единственного зарегистрированного пользователя. Клиентский аккаунт, роль `CLIENT` и client-owned модель остаются Phase 2. Реализация собственного identity-сервера потребовала бы значительных усилий по обеспечению безопасности и поддержке стандартов OIDC/OAuth2, что выходит за рамки MVP.

## Сравнение

| Criteria | Keycloak | Собственный Identity Server |
|----------|:---:|:---:|
| OIDC/OAuth2 support | ✅ | ⚠️ |
| Безопасная выдача JWT | ✅ | ⚠️ |
| Роль `TRAINER` для trainer-first MVP | ✅ | ✅ |
| Future роли client/trainer для Phase 2 | ✅ | ✅ |
| Стоимость реализации для MVP | ✅ | ❌ |
| Контроль доменной авторизации FitBridge | ✅ | ✅ |
| Operational complexity | ⚠️ | ❌ |

## Решение

Использовать Keycloak как внешний Identity Server для аутентификации зарегистрированных пользователей. В MVP публичного доступа к плану это тренер; публичный клиентский доступ по ссылке не использует Keycloak/JWT и проверяется FitBridge Backend через capability-token hash/TTL/revoke. Доменные правила доступа, проверки ownership и авторизация бизнес-операций остаются внутри FitBridge и не делегируются Keycloak.

## Обоснование

- Keycloak — зрелое open-source решение с полной поддержкой OIDC/OAuth2, что снижает риск ошибок при самостоятельной реализации аутентификации.
- Разделение IAM и бизнес-домена позволяет развивать систему авторизации независимо от основной логики FitBridge.
- Keycloak предоставляет встроенную поддержку ролей, групп и клиентских приложений, что покрывает потребности MVP в роли тренера и будущий переход к клиентским ролям.
- Использование стандартного протокола упрощает будущую интеграцию с мобильными клиентами и внешними сервисами.

## Последствия

- Положительно: снижается риск собственной реализации IAM; используется стандартный OIDC/OAuth2 поток.
- Положительно: Keycloak можно развивать отдельно от бизнес-домена FitBridge.
- Отрицательно: появляется отдельный критичный runtime-контур и хранилище Keycloak, требующее мониторинга и резервного копирования.
- Риск: ошибочная настройка realm, clients или roles может нарушить доступ. Митигация: инфраструктурные конфигурации, ревью и тесты auth-flow.
