# ADR-006: Единый стек observability на базе GreptimeDB и Fluent Bit для MVP

**Статус:** Accepted
**Дата:** 2026-08-04

## Контекст

Для успешного проведения пилота FitBridge MVP необходим надёжный, но легковесный observability-контур. Команде важно отслеживать доступность системы, метрики производительности, ошибки API и бизнес-события через структурированное логирование.

Изначально утверждённый стек на базе OpenSearch оказался избыточным и ресурсоёмким для инфраструктуры MVP. В качестве альтернативы рассматривалась GreptimeDB совместно с Grafana. Для уменьшения инфраструктурного футпринта решено отказаться от отдельной системы визуализации и использовать встроенный GreptimeDB Dashboard.

## Сравнение

| Criteria | GreptimeDB + Fluent Bit | OpenSearch + UI + Fluent Bit | Loki + Grafana + Promtail |
|---|:---:|:---:|:---:|
| Контур MVP без внешнего SaaS | ✅ | ✅ | ✅ |
| Полнотекстовый поиск и фильтрация | ✅ | ✅ | ⚠️ |
| Приём структурированных JSON-логов | ✅ | ✅ | ✅ |
| UI для support/debugging | ✅ | ✅ | ✅ |
| Операционная простота для MVP | ✅ | ⚠️ | ⚠️ |
| Достаточность для MVP audit-oriented logs | ✅ | ✅ | ⚠️ |
| Оптимизация для Time-Series | ✅ | ⚠️ | ⚠️ |

## Решение

Использовать **GreptimeDB + Fluent Bit** как observability-стек MVP.

Целевой контур включает:

- Fluent Bit как агент доставки структурированных логов из `stdout`/`stderr` контейнеров;
- GreptimeDB как хранилище и поисковый движок для логов и метрик;
- встроенный GreptimeDB Dashboard как веб-интерфейс для мониторинга и support/debugging;
- masked JSON-события от backend API и инфраструктурных контейнеров;
- Training Service и Caddy используют Docker `fluentd` logging driver и единый Fluent Bit input; access logs Caddy сохраняются без URL query, JWT и request body;
- health endpoint Fluent Bit на `:2020`.

Расширенный продуктовый `AuditEvent` API не входит в MVP. Audit-oriented события фиксируются как masked structured logs без раскрытия лишних данных.

## Обоснование

- GreptimeDB подходит для унифицированного хранения метрик и структурированных логов.
- GreptimeDB потребляет меньше ресурсов, чем JVM-ориентированный OpenSearch, что важно для локальных и MVP-стендов.
- Встроенный Dashboard закрывает базовые задачи просмотра и отладки без отдельного контейнера Grafana.
- Fluent Bit отправляет данные в GreptimeDB через стандартный HTTP output.

## Последствия

**Positive:**
- Более легковесная инфраструктура по сравнению с OpenSearch.
- Меньше контейнеров и конфигурации для локального запуска.

**Negative:**
- Смена стека требует перенастройки Fluent Bit.
- Возможности встроенной визуализации ограниченнее Grafana; при необходимости сложной аналитики Grafana может быть добавлена позже.
