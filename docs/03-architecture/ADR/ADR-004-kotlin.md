# ADR-004: Использовать Kotlin как основной язык

**Статус:** Accepted
**Дата:** 2026-05-19

## Context

Домен FitBridge требует выразительной модели для описания команд, профилей пользователей, механизмов доступа, тренировочных программ и отчётов о выполнении. Необходима хорошая поддержка JVM-экосистемы для интеграции с Ktor, Keycloak и хранилищами данных.

## Comparison

| Criteria | Kotlin | Java |
|----------|:---:|:---:|
| Идиоматичная работа с Ktor | ✅ | ⚠️ |
| Выразительная доменная модель | ✅ | ⚠️ |
| Null-safety на уровне языка | ✅ | ⚠️ |
| JVM ecosystem compatibility | ✅ | ✅ |
| Требования к единому стилю команды | ⚠️ | ✅ |
| Fit for JVM/Ktor stack | ✅ | ⚠️ |

## Decision

Использовать Kotlin как основной язык backend-кода и доменной модели FitBridge. Все новые модули, сервисы и доменные сущности разрабатываются на Kotlin, а Java-библиотеки подключаются через стандартную interoperability.

## Rationale

- Kotlin предоставляет выразительные средства моделирования домена: data classes, sealed classes, extension functions и null-safety, что снижает количество runtime-ошибок.
- Полная совместимость с JVM позволяет использовать любую Java-библиотеку и интегрироваться с Ktor, Keycloak client libraries и JDBC-драйверами без ограничений.
- Kotlin-first подход согласуется с выбором Ktor как backend framework, который спроектирован специально для Kotlin и предоставляет идиоматичный DSL для маршрутизации и middleware.
- Строгая типизация и современные языковые конструкции ускоряют разработку и упрощают рефакторинг доменной модели по мере роста проекта.

## Consequences

- Положительно: лаконичная доменная модель и строгая типизация.
- Положительно: совместимость с JVM, Ktor и Kotlin-first backend stack.
- Отрицательно: команда должна поддерживать единый стиль Kotlin-кода и следить за идиоматичностью решений.
- Риск: возможная сложность совместимости библиотек. Митигация: проверять версии зависимостей и фиксировать решения в ADR.
