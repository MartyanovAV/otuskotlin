# ADR-007: Публичная ссылка на план как capability-token доступ без клиентской регистрации

## Статус

**Rejected / Archived для текущего MVP Trainer Diary.**

Решение отклонено после пересмотра MVP scope: текущий MVP покрывает только управление клиентской базой и тренировочными планами тренера (`clientCard.create/search`, `trainingPlan.create/search`). Share/access-сценарии, отдельный клиентский контур, дневник выполнения, чтение статуса выполнения и сводные экраны исключены.

## Контекст

Реализует [BR-010](../../01-business/BR/BR-010-public-plan-link-mvp.md) и уточняет архитектурные границы [MVP_SCOPE_SUMMARY](../../01-business/MVP_SCOPE_SUMMARY.md).

Первоначальный вариант MVP должен был проверить trainer-first B2B-ценность через публичную ссылку: тренер — единственный зарегистрированный пользователь, создаёт `ClientCard`, создаёт `TrainingPlan`, получает публичную ссылку, клиент без регистрации открывает план и оставляет отметку выполнения, тренер видит статус и может закрыть доступ по ссылке.

Новый MVP **Trainer Diary** сужен до управления клиентской базой и планами. Поэтому публичный доступ по capability-token больше не реализуется в рамках текущего MVP.

Ранее архитектурные документы ориентировались на более широкую client-owned модель с `ClientProfile`, `Invite`, `AccessGrant`, дневником и solo-client путём. Эти концепты остаются стратегическим направлением, но не входят в MVP Trainer Diary.

## Сравнение

Сравнение вариантов относительно [BR-010](../../01-business/BR/BR-010-public-plan-link-mvp.md):

| Критерий | [Вариант A: публичный доступ через capability-token](../proposals/OPT-A-public-plan-access.md) | Вариант B: клиентский аккаунт + `AccessGrant` сразу | Вариант C: обычная share-ссылка без lifecycle |
|----------|:---:|:---:|:---:|
| Клиент без регистрации | ✅ | ❌ | ✅ |
| Time-to-first-plan-link | ✅ | ⚠️ | ✅ |
| Тренер может закрыть доступ | ✅ | ✅ | ❌/⚠️ |
| Не расширяет MVP до client-owned модели | ✅ | ❌ | ✅ |
| Guardrails для public access | ✅ | ✅ | ❌ |
| Путь к будущим `ClientProfile`/`Invite`/`AccessGrant` | ✅ | ✅ | ⚠️ |
| Стоимость реализации MVP | Low/Medium | High | Low |
| Privacy/security риск | Medium при guardrails | Low/Medium | High |

## Решение

**Отклонено для текущего MVP:** вариант A — публичный доступ через capability-token к конкретному `TrainingPlan`.

Архитектурно фиксируем архивное состояние решения:

- текущий MVP содержит только `ClientCard` и `TrainingPlan` как product entities;
- дневник выполнения не входит в текущий MVP;
- публичная ссылка, access token/hash, public-link lifecycle и public endpoints не входят в текущий MVP;
- сводные экраны и чтение статуса выполнения не входят в текущий MVP;
- полноценные `ClientProfile`, `Invite`, `AccessGrant`, client-owned history и клиентский кабинет остаются Phase 2 / future scope и требуют нового ADR.

## Обоснование

Причина отклонения — изменение бизнес-сценария MVP:

- первая ценность теперь проверяется через создание и поиск клиентских карточек и планов;
- система не строит публичный контур, token lifecycle и completion flow до подтверждения необходимости;
- API и ERD упрощаются и не содержат public-link/access-token состояния;
- будущий share/access сценарий должен быть принят отдельным решением, а не наследоваться автоматически из этого ADR.

## Последствия

**Положительные:**
- MVP scope становится согласованным с Trainer Diary: клиентская база + планы.
- Доменная модель упрощается до `ClientCard` и `TrainingPlan`.
- Уменьшается security/privacy поверхность: нет raw token, public URL, public payload и отметок выполнения.

**Отрицательные:**
- Клиент в MVP не получает план по публичной ссылке и не оставляет отметки выполнения.
- Проверка гипотезы share-сценария переносится за пределы MVP.

**Риски:**

| Риск | Вероятность | Влияние | Митигация |
|------|------------|--------|------------|
| Архивное решение случайно реализуют в коде/API | Medium | High | OpenAPI и ERD очищены от share/access-состояний и клиентского дневника; ADR помечен Rejected/Archived |
| Потеря контекста по будущему share-сценарию | Medium | Medium | Сохранять ADR как архивный материал; для возврата сценария создать новый ADR |
| MVP незаметно расширится до client-owned scope | Medium | Medium | `ClientProfile`, `Invite`, `AccessGrant`, клиентский кабинет и solo-client путь явно помечены Phase 2 |
