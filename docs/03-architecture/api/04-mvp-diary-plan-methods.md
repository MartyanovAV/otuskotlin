# MVP Diary and Plan API Methods

Методы Gate 1 для дневника, простых планов, назначений и отметок выполнения.

#### 2. Бизнес-функции (методы)

Все методы используют единый стиль именования `domain.action`. Нумерация методов локальная внутри этого файла.

**[MVP] Тренировочный дневник (BR-001)**

1. **`diary.createEntry`** — создать запись дневника.
    - *Бизнес-правило*: клиент может создавать любые свои записи; тренер может создавать записи только при активном `AccessGrant` и scope `DIARY_WRITE`. Это право относится к тренировочному дневнику и не даёт write-доступ к `ClientProfile`.
    - *Валидация*: `occurredAt` не позже текущего времени + 10 минут, `durationMinutes` 0-600, `intensity` 1-10.
    - *Лимит*: 120 записей/сутки на клиента.

2. **`diary.readEntry`** — получить запись дневника.
    - *Бизнес-правило*: тренер видит запись только при активном доступе на дату запроса.

3. **`diary.updateEntry`** — изменить запись дневника.
    - *Бизнес-правило*: автор может редактировать запись в рамках доступных ему diary permissions; клиент-владелец может редактировать любую свою запись. Тренерская правка записи дневника не является редактированием клиентского профиля.

4. **`diary.deleteEntry`** — удалить запись дневника.
    - *Бизнес-правило*: используется мягкое удаление с возможностью восстановления 30 дней.
    - *Ограничение*: запись, подтверждающая выполнение программы, помечается как удалённая, но агрегаты пересчитываются.

5. **`diary.searchEntries`** — поиск записей дневника.
    - *Фильтры*: период, тип, автор, программа, упражнение, интенсивность.
    - *Лимит*: 60 поисковых запросов/минуту на пользователя.

**[MVP] Простые планы (BR-004)**

6. **`program.create`** — создать программу.
    - *Бизнес-правило*: тренер или клиент могут создавать простые планы.
    - *Валидация*: название 3-120 символов, минимум одна тренировка для статуса `ACTIVE`.

7. **`program.read`** — получить программу.
    - *Бизнес-правило*: доступно автору или клиенту, которому назначена программа.

8. **`program.update`** — изменить программу.
    - *Бизнес-правило*: изменение программы, которая уже назначена, должно корректно отражаться в дневнике или требовать миграции.

9. **`program.delete`** — архивировать программу.
    - *Бизнес-правило*: активные назначения не удаляются; программа получает статус `ARCHIVED`.

10. **`program.assign`** — назначить программу клиенту.
    - *Бизнес-правило*: тренеру требуется активный `AccessGrant` со scope `PROGRAM_WRITE`. Клиент может назначить программу самому себе.
    - *Валидация*: `startDate` не раньше 30 дней в прошлом, программа в статусе `ACTIVE`.

11. **`program.readAssignment`** — получить назначение программы.
    - *Бизнес-правило*: доступно клиенту и назначившему тренеру.

12. **`program.updateAssignment`** — изменить расписание или статус.
    - *Бизнес-правило*: пауза более 30 дней требует подтверждения клиента или тренера.

13. **`program.deleteAssignment`** — отменить назначение программы.
    - *Бизнес-правило*: отмена не удаляет уже созданные записи дневника.

14. **`program.completeWorkout`** — отметить тренировку программы выполненной.
    - *Бизнес-правило*: создаёт или связывает `TrainingEntry` с назначением; клиент или тренер с активным `AccessGrant` и training-domain permissions может фиксировать выполнение в рамках тренировочного процесса без изменения `ClientProfile`.
    - *Валидация*: нельзя завершить тренировку вне периода назначения без комментария.

15. **`program.trackCompletion`** — получить прогресс выполнения назначения.
    - *Бизнес-правило*: тренер видит только клиентов с активным доступом; клиент видит собственный прогресс всегда.
