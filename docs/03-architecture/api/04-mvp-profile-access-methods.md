# MVP Profile and Access API Methods

Методы Gate 1 для профилей, онбординга, приглашений и контроля доступа.

#### 2. Бизнес-функции (методы)

Все методы используют единый стиль именования `domain.action`. Методы изменения данных создают событие `audit.createEvent`, если действие влияет на доступ, персональные данные, дневник, план, подписку или платёж.

Методы в блоках **[MVP]** входят в Gate 1. Методы в блоках **[Phase 2]** и **[Design reserve]** описаны для будущей совместимости и не должны попадать в обязательный первый релиз.

**[MVP] Профили и онбординг (BR-006)**

1. **`profile.createClientProfile`** — создать клиентский профиль.
   - *Бизнес-правило*: один пользователь может иметь только один основной клиентский профиль в MVP.
   - *Валидация*: `fullName` 2-120 символов, `heightCm` 80-250, дата рождения не в будущем.
   - *Лимит*: 10 запросов/час на пользователя.

2. **`profile.readClientProfile`** — получить клиентский профиль.
   - *Бизнес-правило*: доступен владельцу, администратору или тренеру с активным `AccessGrant` и нужным scope.
   - *Ограничение*: скрывать медицинские ограничения, если scope не включает `PROFILE_HEALTH_READ`.

3. **`profile.updateClientProfile`** — изменить клиентский профиль.
   - *Бизнес-правило*: владелец может менять все поля; тренер может менять только разрешённые рабочие заметки при наличии scope `PROFILE_WRITE`.
   - *Аудит*: фиксируются изменения целей, ограничений и видимости.

4. **`profile.deleteClientProfile`** — удалить или архивировать профиль клиента.
   - *Scope*: Phase 2 для self-service удаления; в MVP допустима ручная процедура поддержки.
   - *Бизнес-правило*: физическое удаление заменяется архивированием, если есть активные подписки, платежи или аудит.
   - *Ограничение*: активные назначения программ переводятся в `CANCELLED`.

5. **`profile.createTrainerProfile`** — создать профиль тренера.
   - *Бизнес-правило*: доступно пользователям с ролью `TRAINER`; создаёт шаг онбординга `PROFILE_READY`.
   - *Валидация*: `publicName` 2-80 символов, `bio` до 2000 символов.

6. **`profile.readTrainerProfile`** — получить профиль тренера.
   - *Бизнес-правило*: публичные поля доступны по приглашению; служебные счётчики доступны только владельцу.

7. **`profile.updateTrainerProfile`** — обновить профиль тренера.
   - *Бизнес-правило*: сертификаты могут иметь статус `UNVERIFIED` до проверки.
   - *Лимит*: не более 20 изменений профиля/сутки.

8. **`profile.deleteTrainerProfile`** — архивировать профиль тренера.
   - *Scope*: Phase 2 для self-service удаления; в MVP допустима ручная процедура поддержки.
   - *Бизнес-правило*: нельзя архивировать профиль при активных клиентах без передачи или отзыва доступов.

9. **`onboarding.startTrainerWizard`** — начать мастер первого клиента.
   - *Scope*: MVP как минимальный сценарий подключения первого клиента, не полноценный onboarding playbook.
   - *Бизнес-правило*: запускается после заполнения минимального профиля тренера.
   - *Выход*: следующий шаг подключения клиента.

10. **`onboarding.completeTrainerWizard`** — завершить онбординг тренера.
    - *Бизнес-правило*: статус `COMPLETED` присваивается после создания профиля и первого приглашения или ручного пропуска шага.

11. **`dashboard.getTrainerSummary`** — получить сводку кабинета тренера.
    - *Scope*: MVP возвращает список клиентов, статусы приглашений, статусы доступов и текущие назначения; Phase 2 добавляет alerts, отчёты и billing status.
    - *Бизнес-правило*: учитываются только клиенты с активным доступом.
    - *Метрики*: активные клиенты, ожидающие приглашения, текущие назначения.

**[MVP] Контроль доступа и приглашения (BR-002)**

12. **`access.createInvite`** — создать приглашение клиента или тренера.
    - *Scope*: MVP поддерживает приглашение `TRAINER_TO_CLIENT`; остальные типы относятся к Phase 2/design reserve.
    - *Бизнес-правило*: приглашение от тренера не даёт доступа до явного принятия клиентом.
    - *Валидация*: email в формате RFC 5322, `proposedScopes` не пустой, срок действия 1-30 дней.
    - *Лимит*: MVP — 20 приглашений/сутки на тренера; Coach Pro и Studio Team относятся к Phase 2/design reserve.

13. **`access.readInvite`** — получить приглашение по идентификатору или токену.
    - *Бизнес-правило*: токен показывается только один раз; в базе хранится только хэш.

14. **`access.updateInvite`** — изменить приглашение до принятия.
    - *Бизнес-правило*: можно менять только scopes, комментарий и срок действия; нельзя менять получателя.

15. **`access.deleteInvite`** — отменить приглашение.
    - *Бизнес-правило*: доступно отправителю до статуса `ACCEPTED`.

16. **`access.acceptInvite`** — принять приглашение.
    - *Бизнес-правило*: клиент видит запрашиваемые scopes и подтверждает их явно; создаётся `AccessGrant` в статусе `ACTIVE`.
    - *Аудит*: фиксируются субъект, scopes, источник приглашения и IP.

17. **`access.declineInvite`** — отклонить приглашение.
    - *Бизнес-правило*: повторное приглашение тому же получателю возможно не раньше чем через 24 часа, если не было явного запроса клиента.

18. **`access.grant`** — выдать доступ тренеру без приглашения, если обе стороны уже зарегистрированы.
    - *Бизнес-правило*: только владелец `ClientProfile` может выдать доступ.
    - *Валидация*: scopes должны соответствовать поддерживаемой матрице разрешений.

19. **`access.readGrant`** — получить конкретное разрешение.
    - *Бизнес-правило*: доступно клиенту-владельцу, получившему доступ тренеру и администратору.

20. **`access.updateGrant`** — изменить scopes или срок действия доступа.
    - *Scope*: Phase 2. В MVP расширение доступа выполняется через новый invite/accept flow или ручную миграцию.
    - *Бизнес-правило*: расширение scopes требует подтверждения клиента; сужение может выполнить клиент в один шаг.

21. **`access.revoke`** — отозвать доступ тренера.
    - *Бизнес-правило*: отзыв вступает в силу немедленно; тренер теряет доступ к дневнику, замерам, отчётам и новым изменениям.
    - *Ограничение*: исторические `AuditEvent` не удаляются.

22. **`access.listGrants`** — список активных и исторических доступов клиента.
    - *Scope*: MVP должен уметь показать текущего активного тренера и историю отзыва; расширенные фильтры относятся к Phase 2.
    - *Бизнес-правило*: клиент видит все доступы; тренер видит только свои связи.

23. **`access.validateScope`** — проверить право на действие перед бизнес-операцией.
    - *Бизнес-правило*: отказ доступа должен быть безопасным по умолчанию (`deny by default`).
    - *Метрика*: 99% проверок доступа < 50 мс.
