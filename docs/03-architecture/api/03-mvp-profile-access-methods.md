# Методы Profile and Access API MVP

Канонические методы Gate 1 для профилей, онбординга, приглашений и контроля доступа. Все методы используют стиль `domain.action`.

## Общие правила

- Авторизация: см. [Security Architecture](../SECURITY_ARCHITECTURE.md). Domain API MVP — `CLIENT`/`TRAINER` only, без in-product `ADMIN`/support bypass.
- ClientProfile: `gender` и `goals` — optional/nullable MVP; `heightCm` и body metrics — Phase 2.
- Scopes: trainer `PROFILE_WRITE` для `ClientProfile` запрещён в MVP; доступ тренера основан на active `AccessGrant` и нужном scope.

## Бизнес-функции

**[MVP] Профили и онбординг (BR-006)**

1. **`profile.createClientProfile`** — создать клиентский профиль.
   - *Бизнес-правило*: один пользователь может иметь только один основной клиентский профиль в MVP.
   - *Валидация*: `fullName` 2-120 символов; `gender` и `goals` — optional/nullable MVP поля и не блокируют onboarding. `heightCm` не является supported MVP полем и не валидируется как часть `ClientProfile` до Phase 2.
   - *Лимит*: 10 запросов/час на пользователя.

2. **`profile.readClientProfile`** — получить клиентский профиль.
   - *Бизнес-правило*: доступен клиенту-владельцу или тренеру с активным `AccessGrant` и `PROFILE_READ`; тренеру возвращаются только разрешённые поля.

3. **`profile.updateClientProfile`** — изменить клиентский профиль.
   - *Бизнес-правило*: изменять клиентский профиль может только владелец; владелец может установить, изменить или очистить `gender` и `goals`.

4. **`profile.deleteClientProfile`** — удалить или архивировать профиль клиента.
   - *Бизнес-правило*: физическое удаление заменяется архивированием; пользовательский domain method выполняется владельцем профиля.
   - *Ограничение*: активные назначения программ переводятся в `CANCELLED`.

5. **`profile.createTrainerProfile`** — создать профиль тренера.
   - *Бизнес-правило*: доступно пользователям с ролью `TRAINER`; создаёт шаг онбординга `PROFILE_READY`.
   - *Валидация*: `publicName` 2-80 символов, `bio` до 2000 символов.

6. **`profile.readTrainerProfile`** — получить профиль тренера.
   - *Бизнес-правило*: публичные поля доступны по приглашению; служебные счётчики доступны только владельцу.

7. **`profile.updateTrainerProfile`** — обновить профиль тренера.
   - *Лимит*: не более 20 изменений профиля/сутки.

8. **`profile.deleteTrainerProfile`** — архивировать профиль тренера.
   - *Бизнес-правило*: нельзя архивировать профиль при активных клиентах без отзыва доступов.

9. **`onboarding.startTrainerWizard`** — начать мастер первого клиента.
   - *Бизнес-правило*: запускается после заполнения минимального профиля тренера.
   - *Выход*: следующий шаг подключения клиента.

10. **`onboarding.completeTrainerWizard`** — завершить онбординг тренера.
    - *Бизнес-правило*: статус `COMPLETED` присваивается после создания профиля и первого приглашения или ручного пропуска шага.

11. **`dashboard.getTrainerSummary`** — получить сводку кабинета тренера.
    - *Бизнес-правило*: учитываются только клиенты с активным доступом.
    - *Метрики*: активные клиенты, ожидающие приглашения, текущие назначения.

**[MVP] Контроль доступа и приглашения (BR-002)**

12. **`access.createInvite`** — создать приглашение клиента.
    - *Бизнес-правило*: приглашение от тренера не даёт доступа до явного принятия клиентом.
    - *Валидация*: email в формате RFC 5322, `proposedScopes` не пустой, срок действия 1-30 дней; для MVP `proposedScopes` не должен содержать `PROFILE_WRITE` для клиентского профиля.
    - *Лимит*: 20 приглашений/сутки на тренера.

13. **`access.readInvite`** — получить приглашение по идентификатору или токену.
    - *Бизнес-правило*: токен показывается только один раз; в базе хранится только хэш.

14. **`access.deleteInvite`** — отменить приглашение.
    - *Бизнес-правило*: доступно отправителю до статуса `ACCEPTED`; отмена переводит `Invite.status` в `CANCELLED` и не создаёт `AccessGrant`.

15. **`access.acceptInvite`** — принять приглашение.
    - *Бизнес-правило*: клиент видит запрашиваемые scopes и подтверждает их явно; `Invite.status` становится `ACCEPTED`, создаётся `AccessGrant` в статусе `ACTIVE`. MVP grant может включать `PROFILE_READ` и training-domain scopes (`DIARY_*`, `PROGRAM_*`), но не trainer `PROFILE_WRITE` для `ClientProfile`.

16. **`access.declineInvite`** — отклонить приглашение.
    - *Бизнес-правило*: `Invite.status` становится `DECLINED`; `AccessGrant` не создаётся. Повторное приглашение тому же получателю возможно не раньше чем через 24 часа, если не было явного запроса клиента.

17. **`access.readGrant`** — получить конкретное разрешение.
     - *Бизнес-правило*: доступно только клиенту-владельцу и тренеру, получившему этот доступ.

18. **`access.revoke`** — отозвать доступ тренера.
    - *Бизнес-правило*: отзыв вступает в силу немедленно; тренер теряет `PROFILE_READ` к разрешённым полям профиля, а также доступ к дневнику и планам.

19. **`access.listGrants`** — список активных и исторических доступов клиента.
    - *Бизнес-правило*: клиент видит все доступы; тренер видит только свои связи.

20. **`access.validateScope`** — проверить право на действие перед бизнес-операцией.
     - *Бизнес-правило*: отказ доступа безопасен по умолчанию (`deny by default`).
     - *Метрика*: P99 < 100 мс согласно каноническим API SLO в `06-metrics-and-limits.md`.
