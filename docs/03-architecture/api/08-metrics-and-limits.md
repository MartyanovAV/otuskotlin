# API Metrics and Limits

Продуктовые метрики, performance targets, rate limits и требования надёжности.

#### 4. Бизнес-метрики успеха

**Продуктовые метрики**

| Метрика | Целевое значение MVP | Комментарий |
|---------|----------------------|-------------|
| Активация тренера | ≥ 60% зарегистрированных тренеров создают профиль и отправляют первое приглашение за 24 часа | BR-006 |
| Принятие приглашений | ≥ 50% приглашений принимаются клиентами за 7 дней | BR-002 |
| Ведение дневника | ≥ 3 записи дневника в неделю у активного клиента | BR-001 |
| Назначение плана | ≥ 55% новых тренеров назначают первый план в течение 7 дней | BR-004 |
| Отметка выполнения | ≥ 50% подключённых клиентов отмечают выполнение хотя бы одной назначенной тренировки | BR-005 |

**Производительность API**

| Операция | Ожидание | Порог |
|----------|----------|-------|
| Проверка доступа `access.validateScope` | P99 < 100 мс | Критический путь всех приватных операций |
| Создание записи дневника | P95 < 500 мс | Без загрузки фото |
| Поиск дневника за 12 месяцев | P95 < 1200 мс | До 1000 записей клиента |
| Минимальный список клиентов тренера | P95 < 1000 мс | MVP |
| Открытие истории клиента | P95 < 1000 мс | MVP |
| Назначение плана | P95 < 800 мс | Статус виден через pull-model read endpoints; без отдельного `Notification` API в MVP |
| Логирование audit-oriented события | Не блокирует бизнес-ответ API сверх целевого P95 | Structured logs через ADR-006; retry/доставка в OpenSearch не должны менять бизнес-результат операции |

**Rate limits и ограничения**

| Область | Лимит MVP | Примечание |
|---------|-----------|------------|
| Аутентифицированные чтения | 600 запросов/минуту на пользователя | Общий API gateway limit |
| Операции записи | 120 запросов/минуту на пользователя | Кроме специальных лимитов ниже |
| Создание записей дневника | 120 записей/сутки на клиента | Защита от импорта через ручной ввод |
| Поиск дневника и планов | 60 запросов/минуту | На пользователя |
| Приглашения MVP | 20 приглашений/сутки | На тренера в пилоте |

**Надёжность и соответствие**

1. Доступность публичного API MVP: 99,5% в месяц.
2. Потеря подтверждённых записей дневника: 0 допустимых случаев.
3. Время вступления отзыва доступа в силу: не более 5 секунд для пользовательских API.
4. Scope уведомлений MVP ограничен pull-model UI статусами в существующих read endpoints/dashboard; push/email provider и отдельный `Notification` API — Phase 2.
5. Scope аудита MVP ограничен infrastructure audit-oriented logging по ADR-006; продуктовый `AuditEvent` API и отдельная audit entity — Phase 2.
