# BR-002: Контроль доступа к данным клиента

## Статус

| Параметр | Значение |
|----------|----------|
| **Статус** | ⬜ Черновик |
| **Дата утверждения** | 2026-04-29 |
| **Комментарий** | Ключевая дифференциация client-owned data |

## Business Value

Даёт клиенту контроль над данными, повышает доверие и снижает потери истории при смене тренера.

## User Stories

### US-R002-001: Выдача и отзыв доступа тренерам

* **As a** клиент
* **I want** выдавать и отзывать доступ тренерам
* **So that** только выбранные специалисты видели мой прогресс

**Acceptance Criteria:**

* **AC-R002-U001-001:**
    * **Given:** у меня есть профиль
    * **When:** я приглашаю тренера по ссылке или коду
    * **Then:** доступ выдаётся только после моего подтверждения
* **AC-R002-U001-002:**
    * **Given:** тренер уже подключён
    * **When:** я отзываю доступ
    * **Then:** тренер теряет право просмотра и редактирования
* **AC-R002-U001-003:**
    * **Given:** у меня несколько специалистов
    * **When:** я открываю экран доступов
    * **Then:** вижу кто и к каким данным имеет доступ

### US-R002-002: Смена тренера без потери истории

* **As a** клиент
* **I want** сменить тренера без потери данных
* **So that** мой прогресс оставался со мной

**Acceptance Criteria:**

* **AC-R002-U002-001:**
    * **Given:** у меня есть история занятий
    * **When:** я отключаю старого тренера
    * **Then:** история остаётся в профиле без удаления
* **AC-R002-U002-002:**
    * **Given:** я подключил нового тренера
    * **When:** выдаю ему доступ
    * **Then:** он видит накопленный baseline

## System Constraints

| Constraint   | Value     | Notes |
|--------------|-----------|-------|
| Latency      | < 1000 ms | Операции с доступами |
| Throughput   | 20 req/sec | Пиковые операции редки |
| Availability | 99.9%     | Критично для доверия и комплаенса |

## Out of Scope

- Публичный обмен данными между пользователями
- Неограниченное делегирование прав третьим лицам
